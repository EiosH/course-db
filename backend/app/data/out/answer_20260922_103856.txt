Collections: Fold Left vs. Fold Right

How does Scala implement foldLeft and foldRight?

package scala.collection
trait LinearSeqOps[A, +CC[X] <: LinearSeq[X],
  +C <: LinearSeq[A] with LinearSeqOps[A, CC, C]] {
  // ...
  override def foldLeft[B](z: B)(op: (B, A) => B): B = {
    var acc = z
    var these: LinearSeq[A] = coll
    while (!these.isEmpty) {
      acc = op(acc, these.head)   // <-- Ed.: Lipstick on a pig.
      these = these.tail
    }
    acc
  }
}

package scala.collection.immutable.List
sealed abstract class List[+A] extends /* ... */ {
  // ...
  final override def foldRight[B](z: B)(op: (A, B) => B): B = {
    var acc = z
    var these: List[A] = reverse   // <-- Ed.: Lipstick on a pig.
    while (!these.isEmpty) {
      acc = op(these.head, acc)     // <------ Airbrushed!
      these = these.tail
    }
    acc
  }

  final override def reverse: List[A] = {
    var result: List[A] = Nil
    var these = this
    while (!these.isEmpty) {
      result = these.head :: result
      these = these.tail
    }
    result
  }
}

答案:
Yes, the instructor used a **linear search** (finding a specific element) as a simpler example to illustrate why the current implementation is unsatisfying.

The key point is that with the `var` and `while` loop implementation shown on the slide, you **cannot abort early**. Even if you find the element you are looking for at the very beginning of the list, the code is forced to iterate through every single remaining element because it is just a glorified loop. This makes the operation strictly linear time, which is inefficient for a simple "find" operation where you might expect to stop as soon as you find a match.
